# File operations

<Media src="file-operations.gif" alt="Copying, renaming, trashing and undoing" caption="Copy to the next panel, rename, undo, trash and undo again." />

Most actions apply to the **marked** items, or to the item under the cursor when nothing is marked. Mark with <Kbd>space</Kbd>, select a range with <Kbd>v</Kbd>, extend with <Kbd>J</Kbd> / <Kbd>K</Kbd>, mark everything with <Kbd>ctrl+a</Kbd> or by pattern with `:select *.png`.

## Copy and move

| Keys | Action |
| --- | --- |
| <Kbd>y y</Kbd> / <Kbd>x</Kbd> then <Kbd>p</Kbd> | Copy / cut, then paste in another directory |
| <Kbd>c</Kbd> / <Kbd>m</Kbd> | Copy / move straight into the next panel |

If some names already exist in the destination, strata asks once for the whole paste: **keep both** (the new item becomes `name (1).ext`), **overwrite** (replaced items go to the trash on local disks), **skip** those items, or cancel.

Transfers run in the background, so you can keep working. Their progress appears under **Processes** in the footer; <Kbd>alt+p</Kbd> pauses or resumes the latest one and <Kbd>ctrl+x</Kbd> cancels it. If a copy or move fails or is cancelled, <Kbd>alt+R</Kbd> (or `:retry`) picks it up where it stopped: items that finished are left alone, files that already arrived complete are kept, and the rest go into the same destinations as before. Copies work between any locations — local disk, SFTP servers and Docker containers.

## Create, rename, delete

| Keys | Action |
| --- | --- |
| <Kbd>a</Kbd> / <Kbd>A</Kbd> | New file / directory (`docs/notes.md` creates the folder too) |
| <Kbd>r</Kbd> | Rename |
| <Kbd>R</Kbd> | Bulk rename the marked items in `$EDITOR` |
| <Kbd>g r</Kbd> | Rename the marked items with a pattern |
| <Kbd>d d</Kbd> | Move to the trash |
| <Kbd>D</Kbd> | Delete permanently |

Bulk rename opens one name per line in your editor; change the lines, save and quit. Swapping two names works, and strata refuses to overwrite files that are not part of the rename.

## Rename with a pattern

<Kbd>g r</Kbd> (<Kbd>alt+m</Kbd> in the classic preset) asks for a pattern and shows the new names as you type. Enter renames every marked item, in the order they are listed, as one step you can undo. `:rename-pattern <pattern>` does the same without the prompt. Items can be in different folders, for example after a [`:find`](/docs/search/#find-by-size-age-type-or-tag).

A pattern is a template for the whole new name, or a regex substitution:

```text
photo-{n:3}{.ext}             IMG_4821.JPG  → photo-001.JPG
{date}_{name|lower}{.ext}     Notes.TXT     → 2026-10-11_notes.TXT
s/IMG_(\d+)/trip-$1/          IMG_4821.JPG  → trip-4821.JPG
s/ +/_/g                      my file.txt   → my_file.txt
```

| Token | Value |
| --- | --- |
| `{name}`, `{ext}`, `{.ext}` | Name without the extension; the extension without / with its dot (empty when there is none) |
| `{full}` | The whole current name |
| `{n}`, `{n:3}`, `{n:3:10}` | A counter, zero-padded to 3 digits, starting at 10 |
| `{date}`, `{date:%Y%m%d}` | The modification date |
| `{parent}` | The containing folder's name |
| `$1`, `{1}`… | Regex groups, in substitutions |

Add `|upper`, `|lower` or `|title` to any token: `{name|title}`. Substitutions take the flags `g` (every match) and `i` (ignore case). strata refuses a pattern that gives two items the same name or would overwrite another file.

## Tags

<Kbd>,</Kbd> opens the tag menu for the marked items: pick a colour (`red`, `orange`, `yellow`, `green`, `blue`, `purple`, `gray`) or a tag to switch it on or off, or type a new tag and press <Kbd>enter</Kbd>. Tagged items show coloured dots after their names, and every tag gets an entry in the sidebar that lists what carries it.

| Command | Action |
| --- | --- |
| `:tag <name>` / `:untag [name]` | Add a tag / remove one, or all of them |
| `:tags` | Pick a tag and list everything tagged with it |
| `:select tag:<name>` | Mark the listed items with that tag |
| `:find --tag <name>` | Find tagged items below the current folder |
| `:tags prune` | Forget the tags of items that no longer exist |

Tags are kept in `~/.local/share/strata/tags.tsv` and follow items you rename or move in strata, including through undo. On Linux they are also written to the `user.xdg.tags` extended attribute, which other file managers such as Dolphin read and which survives moves made elsewhere.

## Duplicate and link

| Keys | Action |
| --- | --- |
| <Kbd>Y</Kbd> | Duplicate the marked items next to themselves (`name (1).ext`) |
| <Kbd>g l</Kbd> / `:link` | Paste the clipboard as symbolic links |
| <Kbd>g L</Kbd> / `:link -r` | Paste the clipboard as relative symbolic links (`../lib/x`) |
| `:hardlink` | Paste the clipboard as hard links |

Links are made in the focused directory to what you copied with <Kbd>y y</Kbd>, and get a ` (1)` suffix when the name is taken. Symbolic links work on the local disk, SFTP servers and in Docker containers; hard links on the local disk and in containers.

## Permissions and owners

<Kbd>=</Kbd> asks for new permissions for the marked items, starting from the hovered item's current mode. Type an octal mode (`644`, `2755`) or a symbolic one like `chmod` takes (`u+x`, `go-w`, `a=rX`, `u=rwx,go=rx`). Start with `-R` to change everything below directories too; symbolic links met on the way are left alone. The same works as `:chmod [-R] <mode>`.

`:chown [-R] user[:group]` (or `:group`) changes the owner of local items. Names are looked up the way `id` and `getent` do, so LDAP users work too. Changing owners usually needs root.

## Compare

<Kbd>C</Kbd> compares two items:

- two **marked** items in the same panel, or
- the hovered item with the item of the same name in the next panel (or, if there is none, the item hovered there).

Two text files open as a coloured unified diff. Binary or large files (over 4 MiB) only report whether they differ. Two directories are compared recursively: the report lists what differs and what exists on one side only. Comparisons run in the background and work across local, SFTP and Docker locations.

To use your own diff tool for local files, set it in the config:

```toml
[general]
diff_tool = "nvim -d"   # or "meld", "code --diff --wait", "delta"…
```

## Sync

`:sync` makes the next panel's folder match the focused one, one way: it copies what is missing there and replaces files whose contents differ. Nothing changes until you confirm the plan, which shows how many items it will copy, replace and delete, and how much it will copy.

| Option | Effect |
| --- | --- |
| `--mirror` | Also delete what only the destination has |
| `--newer` | Replace a differing file only when the source copy is newer |
| `--dry-run` | Only list what would happen: `+` copy, `~` replace, `-` delete |

Files are compared by content, like <Kbd>C</Kbd>, so a sync works across local, SFTP and Docker locations. Replaced and deleted items go to the trash on local folders, and the whole sync can be undone; on remote folders they are removed for good, and only the copies can be undone. One failing item does not stop the others.

## Duplicates

`:dupes` finds duplicate files below the current folder: files of the same size are compared by content (SHA-256). Empty files, symbolic links and extra hard links to the same file are left out, and so are hidden files unless they are shown. The results open in a list, biggest savings first, numbered by group:

| Keys | Action |
| --- | --- |
| <Kbd>enter</Kbd> | Go to the file |
| <Kbd>ctrl+d</Kbd> | Trash this copy, then show the list again |

`:dupes keep oldest`, `keep newest` or `keep shortest` (the shortest path, usually the original rather than `copy (2)`) trashes every other copy in each group, after asking. Files that changed since the scan are left alone, and the trashing can be undone. Finding duplicates works on local folders.

## Checksums

<Kbd>#</Kbd> shows the MD5, SHA-1 and SHA-256 of the marked files. `:checksum sha256` (or `md5`, `sha1`, `sha512`) copies the hovered file's checksum to the clipboard instead.

To verify a download:

- `:verify <hash>` checks the hovered file against a hash you paste. The algorithm follows from the hash's length.
- `:verify` on a checksum file (`SHA256SUMS`, `MD5SUMS`, `app.iso.sha256`…) checks every file it lists, in GNU (`hash  file`) or BSD (`SHA256 (file) = hash`) format.

## Trash

<Kbd>U</Kbd> (or `:trash`) lists what is in the trash, newest first: name, when it was deleted and where from. Type to filter. In the list:

| Keys | Action |
| --- | --- |
| <Kbd>enter</Kbd> | Restore the item where it came from and show it |
| <Kbd>ctrl+d</Kbd> | Delete the item for good |
| <Kbd>ctrl+e</Kbd> | Empty the trash |

Restoring refuses to replace something that has taken the item's place. Restores can be undone like other operations. `:empty-trash` empties the trash after asking. Browsing the trash works on Linux, the BSDs and Windows; macOS has no API to list it.

## Archives

<Kbd>enter</Kbd> on a zip or tar archive opens it like a directory: `.zip`, `.jar`, `.apk`, `.whl` and other zip-based files, and `.tar` with gzip, bzip2, xz or zstd (`.tar.gz`, `.tgz`, `.tar.bz2`, `.tar.xz`, `.tar.zst`…). Browse and preview inside it, and copy items out with <Kbd>c</Kbd> or <Kbd>y y</Kbd> and <Kbd>p</Kbd>. Archives are read-only: renaming, deleting or pasting into them is refused, and edits to files opened from them are not saved back. <Kbd>h</Kbd> at the archive's root goes back to the folder that holds it.

The archive is indexed once when you open it, and files are read in archive order, so copying a whole `.tar.gz` out decompresses it only once. Set `browse_archives = false` to open archives with the system app instead.

<Kbd>X</Kbd> (or `:extract`) unpacks the hovered archive into the current folder: in place when it holds a single item, otherwise into a folder named after it. It runs as a copy, so it shows progress and can be paused, resumed and undone. Other formats such as `.7z` and `.rar` are handed to 7-Zip when it is installed.

`:compress [name]` packs the marked items, or the hovered one, into an archive; without a name it asks, suggesting `.zip`. strata writes `.zip`, `.tar`, `.tar.gz` and `.tar.bz2` itself, and uses the system `tar` for `.tar.xz` and `.tar.zst`.

## Undo and redo

Press <Kbd>u</Kbd> (or <Kbd>ctrl+z</Kbd> with the classic preset) to undo the last operation, and <Kbd>ctrl+r</Kbd> (<Kbd>ctrl+y</Kbd>) to redo it. Doing something new clears what can be redone. Undo covers:

- renames and bulk renames,
- new files and directories (they go to the trash),
- copies (the copies go to the trash),
- moves (items go back where they came from, even across filesystems),
- trashing (items are restored from the trash — Linux and Windows),
- restores from the trash browser (they go back to the trash),
- links and duplicates (they go to the trash),
- permission and owner changes (the old ones are set again),
- syncs (copies go to the trash, replaced and deleted items come back).

<Callout type="warn">Permanent deletes (<Kbd>D</Kbd>) cannot be undone. strata asks for confirmation unless you set `confirm_delete = false`.</Callout>

## Open files

<Kbd>enter</Kbd> opens text files in your editor, media or documents with the system app, and [archives](#archives) like directories. <Kbd>o</Kbd> always uses the system app, and <Kbd>e</Kbd> / <Kbd>E</Kbd> open the file or the whole directory in your editor. To choose programs per file type, see [`open_with`](/docs/configuration/#open-with).

## Remote files

On SFTP servers and in Docker containers, <Kbd>enter</Kbd> and <Kbd>e</Kbd> download the file to a private temporary folder and open it in your editor. When you quit the editor, strata uploads the file back if you changed it, then deletes the copy.
